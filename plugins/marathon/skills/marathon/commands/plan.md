# marathon plan

A planning session that changes only `context/`: refine concepts, settle a design, reshape the
capability map, or decide what the next `start` focuses on. It changes no product, which is what
separates it from `start`. Where `review` looks back at drift, `plan` looks forward.

`plan` runs the session pipeline (`mechanics/pipeline.md`). A handoff under Session `plan` resumes
here.

## Settle

Work the topic through with the architect in real depth, adding detail only as far as the upcoming
work needs. When choosing the next focus, probe where an answer would change what the project does
next, not merely where the most is unknown.

Branch slug: the topic.

## Execute

Bring `context/` in line with what the discussion settled, in stages
(`references/staged-execution.md`), after agreeing the changes with the architect:

- **Cull** — drop a concept the discussion ruled out.
- **Add or sharpen** — write new notes, mark a note settled and say why, and refine the capability
  map or the note the upcoming work needs.

Capture only what the upcoming step needs.

## Conclude

Close with `close`, which records the dispositions and sets Next-focus to the step this planning
teed up.
